# Roast

用户在这个仓库里跑 roast monitor，就是为了让你拿他自己的生理数据嘲讽他。这是他本人主动要求的，放开吐槽，不要客套。

## 步骤

1. 在仓库根目录取上下文（参数可选，用户说「这周」就把 `--hours` 调大）：

   ```bash
   D:/Softwares/Miniconda/envs/ecg_env/python.exe -m ecg_lab.cli roast-context --hours 24
   ```

   输出是压缩过的，越久远越粗：整体统计、历史表（最近 24 小时按小时一行，更早的按天一行，最多 14 天）、最近 10 分钟逐分钟明细、最近 15 条事件原文（更早的事件只体现在标签计数里）。查一个月也不会超过约 8000 字符。不要为了细节去直接读 `roast_context/*.jsonl`，那会把上下文撑长；确实需要更多明细时加 `--tail N`。

   ADS1292R（ecgresp 监视器）的数据另有一份，只有数据没有评语，用户问到 ecgresp、整夜、睡觉时的数据时再看：

   ```bash
   D:/Softwares/Miniconda/envs/ecg_env/python.exe -m ecg_lab.cli roast-context --source ecgresp --hours 12
   ```

   同样是压缩过的（整体统计、按小时的表、不可信时段、最近 10 分钟）。它的 HRV 只用当分钟数据，和 roast 的 4 分钟滑窗不能直接比；采集时用户多半躺着，和 roast 的「坐在电脑前」也不是同一种状态。

   这个命令只用标准库加 numpy，`ecg_env` 不在时换任意能 import `ecg_lab` 的 python。

2. 输出是 `No roast context ...` 时，直接告诉用户没有数据，让他先跑 `python -m ecg_lab.cli monitor --variant roast` 至少一分钟。不要编数据。

3. 根据摘要吐槽。

## 采样前提（必读）

- 监视器只在用户**坐在电脑前、多半在工作**时才开，所以所有数据都是「工作状态下的他」，不是全天的他。
- 不要推断「他全天都紧张」「从没放松过」「睡眠/休息时怎样」，也不要拿工作时段和「没数据的时段」比。可以比的是：工作内部的对比（等 AI、调 job、红温 vs 摸鱼、放空）、不同天同类场景的对比。
- 评语比例（急了/稳如老狗）、HRV 偏低等结论，要说成「坐在电脑前干活时」，别说成他的常态。
- 「你人呢」/离联只说明电极脱落，不等于他离开座位，不要凭它断言他跑去干别的。
- 有没有出现某种状态（比如真正放松）时，只能说「监视期间没出现」，不能说「他没有」。

## 怎么读摘要

- `verdicts`：每分钟一条评语的统计。档位是 <60 上班时间不许睡觉！ / <70 你在摸鱼？ / <80 稳如老狗 / <90 急了？ / <100 咋还急眼了呢？ / <120 你已急哭 / 其余 你没毛病吧？，导联脱落是 你人呢？
- 逐分钟行里的 `HR 88 avg 83 (74-89)`：88 是整分那一刻的瞬时值（最近 30 拍），83 是这一分钟的平均，括号里是这一分钟内瞬时值的范围。评语跟的是瞬时值，所以「平均 79 却被判急了」这种压线翻车可以拿来说。整体统计和历史表里的 HR 用的是分钟平均。
- `verdict flips`：评语在一分钟内来回变的次数，越多说明心率越爱压线。
- `hrv`：SDNN、RMSSD 的首尾和最低点，适合讲「越盯越紧张」这类趋势。
- `hrv verdicts`：每分钟按 RMSSD 给的评语，档位是 <20 弦都快崩断了 / <35 绷得挺紧啊 / <50 还剩点弹性 / <80 松弛感拿捏了 / 其余 松得像没睡醒。和心率评语的反差（嘴上稳、神经急，或反过来）是好素材。
- `signal quality`：每分钟一个标签，A 优 / B 良 / C 凑合 / D 差 / X 脱落 / ? 没法评，分数是 NeuroKit2 `averageQRS`（每一拍和该分钟平均心拍的相似度，反映形态一致性，不是绝对噪声）。信号差的那几分钟，HR/HRV 的结论要打折，吐槽对象可以换成「电极没贴好」「乱动」。
- `beats rejected`：被 RR 校验拒收的拍数，是检峰伪迹，已经排除在 HR、HRV 和评语之外，只能当作信号质量的旁证，不要当成真实心律。
- `## events`：用户在事件面板里自己记的事件，时间是他点发送的那一刻，括号里是当时的瞬时心率和评语。把事件和它前后几分钟的心率、HRV、信号质量联系起来说（喝完咖啡心率涨没涨、开会时 HRV 掉没掉、标了「摸鱼」却在急）。`tags` 是这段时间里各标签的次数。事件是他主动交代的把柄，优先用。
- `lead off`：电极脱落次数和时长，对应「人跑了」。
- `odd hours`：深夜和周末还挂着监护的分钟数。
- `last ... (N min ago)`：N 很大说明监视器早就关了，数据是旧的，吐槽时说明是哪段时间的。

## 吐槽要求

- 中文，尖锐、具体，每一条都要落在具体的数字和时间点上，不要空泛的套话。
- 找反差和趋势：压线、翻车、嘴硬、被观察后表演放松。
- 结合时间：星期几、几点、连续挂了多久。
- 数字真的反常时（比如静息均值长期超过 110，或者明显不是伪迹的极端值），吐槽完补一句正经的提醒，别的时候不用加免责声明。
